두글 UI/UX 개선 제안

두글은 rhwp 스튜디오 위에 데스크탑 셸(제목 막대·리본·백스테이지)과 AI 편집 에이전트 사이드바를 얹은 포크입니다. 이 문서는 rhwp-studio/src/doogle/**를 읽고, 지금 잘 된 것과 걸리는 것을 짚은 뒤, 우선순위를 매긴 12개 제안과 3단계 로드맵을 제시합니다.

읽은 범위shell/ 12개 파일 · theme/ 3개 · ui/sidebar.ts(1,360줄) · review/ 4개 · agent/pending.ts · index.ts · doogle-desk/src/hub.rs · docs/doogle/PLAN.md, CONTRACT.md, RELEASE.md
읽지 못한 것실행 화면(빌드·dev 서버 금지 조건). mydocs/manual/rhwp_studio_ui_conventions.md는 이 작업 트리에 없어 dg- 접두어·:root[data-doogle] 범위 규칙은 코드에서 역추론했습니다.
표기우선순위 P1(먼저) → P3. 노력 S(1~2일) · M(3~5일) · L(1주 이상). "영향 파일"은 수정이 예상되는 자리입니다.

1현재 UI 읽기

두글 모드(:root[data-doogle])에서 화면은 위에서부터 제목 막대 38px → 리본 탭 34px → 리본 패널 104px → 문서 캔버스(+ 오른쪽 사이드바 420px) → 상태 표시줄 26px로 쌓입니다. 리본은 ribbon-model.ts의 선언 데이터로 그리고, 실행은 전부 window.rhwpStudio.automation.execute를 거쳐 upstream 디스패처와 같은 게이트를 탑니다.

2개선 원칙

  1. 셸은 겉모습, 두뇌는 upstream. 지금 지키고 있는 규칙을 그대로 유지합니다. 새 UI도 automation.execute·PluginHost·기존 DOM 관찰로만 붙이고, 컨트롤러를 복제하지 않습니다. 리베이스 비용이 곧 UX 지속성입니다.
  2. 상태는 한 곳에서 여러 표면으로. reviewStore가 좋은 선례입니다. 문서 dirty·저장·연결 상태도 같은 방식(작은 store + window 이벤트)으로 제목 막대·상태 표시줄·사이드바가 함께 보게 합니다.
  3. 사용자의 언어로. "agent hub", "provider", "스테이징"은 코드 용어입니다. 화면에는 "에이전트 서비스", "AI 계정", "검토 대기 중인 변경"으로 씁니다. 오류는 무엇이 안 됐고 다음에 무엇을 누르면 되는지를 한 문장으로.
  4. 되돌릴 수 있음을 눈에 보이게. 에이전트 편집은 "내 문서 그대로"라는 약속 위에 있습니다(PLAN §1). 거절의 파급, 사용자 편집 혼입, 저장 시 스테이징 포함 여부처럼 되돌림의 경계는 툴팁이 아니라 본문에 드러나야 합니다.

3제안

우선순위는 "사용자가 매일 겪는 빈도 × 잘못됐을 때의 손실 × 구현 위험의 역수"로 매겼습니다. P1 네 개(리본 접기, 제목 막대 상태, 검토 흐름, 사이드바 연결·설정)가 체감을 가장 크게 바꿉니다.

3.1리본 접기와 밀도 모드

P1노력 M셸매일 체감
문제
리본 패널 104px이 항상 펼쳐져 있어 노트북에서 문서가 화면의 73%만 차지합니다. 한글(HWP)·Word 사용자는 리본을 접어 두고 탭을 눌러 꺼내 쓰는 습관이 있는데 그 경로가 없습니다. 또 AI 토글이 탭마다 반복돼 리본이 "AI 단추를 어디 뒀더라"의 문제가 아니라 "왜 또 있지"의 문제가 됩니다.
제안

① 접기 상태: 탭 줄만 남기고 패널을 숨깁니다. 탭을 누르면 패널이 플라이아웃(오버레이)으로 열리고, 문서를 클릭하면 닫힙니다. 전환은 Ctrl+F1, 활성 탭 두 번 클릭, 탭 줄 오른쪽 끝의 ⌃ 단추. 상태는 localStorage['doogle.ribbon']에 기억.

② AI 토글을 탭 줄 오른쪽 상시 자리로 옮기고(사이드바 열림 = 눌림), 각 탭의 'AI' 묶음을 지웁니다. 'AI 도우미' 탭은 검토 관련 묶음(변경 탐색·모두 적용/거절·문서 이력)으로 채우거나, 검토 탭과 합칩니다.

③ 간소화 모드(선택): 한 줄 48px에 자주 쓰는 단추만(글꼴·크기·B/I/U·정렬·표·그림·찾기). ribbon-model.ts에 simple?: boolean 플래그만 더해 같은 데이터로 그립니다.

3.2제목 막대를 문서 상태의 중심으로

P1노력 S셸 · 데스크
문제
"저장했나?"를 알려면 닫기를 눌러 대화상자가 뜨는지 봐야 합니다. 열린 파일이 HWP인지 HWPX인지(저장 시 형식 선택에 영향), 어느 폴더인지도 보이지 않습니다. 업데이트 알약 "업데이트 v1.2"는 텍스트라 상시 노출 시 시선을 끕니다.
제안
  • dirty 점: 제목 앞에 ● (호박색). command-state-changed/document-changed 때 context().isDirty를 읽어 갱신. 저장 직후 1.5초 "저장됨 ✓" 페이드.
  • 형식 배지 HWPX/HWP: 파일명 확장자에서. 호버 시 전체 경로 툴팁(데스크탑).
  • 제목 클릭 → 팝업: 이름 바꾸기(다른 이름으로 저장), 폴더에서 보기(files.rs에 reveal_in_folder 1개 추가), 경로 복사.
  • 업데이트 알약은 아이콘+점으로 줄이고, 설명은 호버·팝오버에.
목업

3.3검토 흐름 재설계: 파급을 보여 주고, 전·후를 보여 주고, 손을 떼지 않게

P1노력 L검토 · 사이드바 · 에이전트제품 핵심
문제

두글의 약속은 "검토 후 적용, 내 문서 그대로"입니다. 그런데 지금 검토 UI는 세 가지를 숨깁니다. (a) 중간 행 거절이 뒤 행을 함께 되돌린다는 사실은 툴팁에만, (b) 변경의 전·후는 한 줄 요약으로만, 서식 변경은 요약조차 없이, (c) 검토 대기 중 사용자가 직접 타이핑하면 거절 시 그 편집도 날아간다는 것은 사후 통지로만.

또 변경이 12쪽 문서 곳곳에 흩어지면 "어디가 바뀌었나"를 알약의 ‹ › 로만 순회해야 합니다.

제안

① 파급 시각화. 검토 행에 마우스를 올리거나 포커스하면, 거절 시 함께 되돌아갈 뒤 행들이 흐려지고 행 아래에 "함께 되돌아감 N건" 배지가 인라인으로 뜹니다. 팝오버의 '거절' 단추도 "거절 (+2)"처럼 숫자를 품습니다.

② 인라인 전·후. 팝오버 윗줄에 이전 → 이후 한 줄(길면 말줄임, 클릭하면 펼침). 서식 변경은 속성 칩으로: 굵게, 10pt → 12pt, 왼쪽 → 양쪽. describe.ts에 props 요약을 추가하고 pending.ts의 PendingChangeTarget에 before/after 서식 스냅샷을 넣습니다.

③ 문서 거터. #scroll-container 오른쪽에 6px 스트립을 두고 변경 위치를 점으로 찍습니다(reviewStore.rows() → 문단 위치 비율). 현재 변경은 파랑, 나머지는 호박색. 클릭하면 그 변경으로.

④ 사용자 편집 혼입 경고. 검토 대기 중 document-changed가 에이전트 외 출처로 발생하면(pending.ts가 revision 비교로 이미 알 수 있음) 알약에 "직접 편집 포함"을 표시하고, 거절 전에 "직접 고친 내용 1건도 함께 되돌아갑니다 — 계속할까요?"를 인라인 확인으로 묻습니다.

⑤ 키보드. Alt+↓/Alt+↑ 다음·이전 변경, Alt+Enter 이 변경 적용, Alt+Backspace 이 변경 거절, Ctrl+Enter 모두 적용(기존). 팝오버가 열리면 단축키를 단추 옆에 작게 표기.

문제

3.11업데이트와 닫기 흐름

P2노력 S셸 · 데스크
문제
  • 업데이트 설치 중에는 팝오버가 닫히지 않아(closePopover가 installing이면 무시) 모달처럼 됩니다. 내려받는 몇십 초 동안 문서를 못 보는 건 아니지만 팝오버가 캔버스를 가립니다.
  • 닫기 가드 대화상자(upstream unsaved-changes-dialog)는 "저장 / 저장 안 함 / 취소"만 묻습니다. 그런데 검토 대기 중인 에이전트 변경은 이미 문서에 적용된 상태(라이브 스테이징)라 "저장"을 누르면 검토하지 않은 변경이 그대로 파일에 들어갑니다. 이 사실을 아무도 알려 주지 않습니다.
제안
  • 설치 진행은 상태 표시줄로 내려보내고 팝오버는 닫을 수 있게. 완료 직전 "곧 다시 시작합니다"만 토스트.
  • 닫기·저장 가드에 검토 상태를 합칩니다. getPendingCount() > 0이면 대화상자 본문에 "검토 대기 중인 에이전트 변경 4건이 문서에 포함돼 있습니다"를 추가하고 단추를 [변경 적용하고 저장] [변경 거절하고 저장] [저장 안 함] [취소]로. upstream 대화상자를 고치지 않고 두글 쪽 confirmLeaveDocument()에서 pending이 있을 때만 두글 대화상자를 띄웁니다.
  • 같은 가드를 file:save 자체에도(저장 직전 pending이 있으면 한 번 묻기, "다시 묻지 않음" 체크 가능).
  • 업데이트 확인 실패는 백스테이지 '정보'에만 남기고 제목 막대엔 아무것도 띄우지 않음(지금처럼 console.info만으로는 사용자가 영영 모름 → 백스테이지에 "마지막 확인: 실패(네트워크)").
